> ### ⚠️ 터치 타깃 52 → 44px 은 **되돌림**이다
>
> §0 의 설계 제약("손이 젖어 있거나 목줄을 잡은 상태")은 **사라지지 않았다.** 44px 은
> WCAG 2.5.5 / iOS 44pt 의 **최소값**이지 이 사용 맥락의 최적값이 아니다. 그래서:
>
> - **44px 아래로는 내려가지 않는다.** mini SaaS 밀도를 더 원하더라도 여기가 바닥이다.
> - 밀도가 필요한 자리는 `size='control'`(36px)로 열어 두었고, **마우스를 전제한
>   데스크톱(lg+) 표·툴바 전용**이다. 모바일 화면에서 쓰려면 `lg:` 로 한정한다.
> - `SegmentedControl` 은 **히트 영역 44px 을 유지한 채 보이는 칩만 36px** 로 줄였다.
>   밀도를 손가락에서 빼지 않는 방법이 이것이다.
> - **현장에서 오조작이 늘면 `--spacing-touch` 를 가장 먼저 되돌린다.**
>
> ### 함께 고친 것 — 원래 깨져 있던 두 가지
>
> 1. **`text-name` 이 어디에도 정의돼 있지 않았다.** 6곳에서 쓰였고 그중 하나가
>    `PageShell` 의 페이지 `<h1>` 이라, **모든 화면의 제목이 본문 크기**로 나오고
>    있었다. 굵기만 살아 "굵은 본문"으로 보여서 아무도 깨진 줄 몰랐다. 제목은
>    `text-title` 로 옮기고 `text-name`(16px)은 **개체 이름 전용**으로 정의했다.
> 2. **`--color-text-meta` 가 색이 아니었다.** 2층 색 별칭 `--text-meta` 를 뒤의
>    `@theme` 에 있는 **타이포 스케일 `--text-meta: 12px`** 가 덮어써서,
>    `text-text-meta` 를 쓰는 38곳이 전부 `color: 12px` 라는 무효값을 받아 부모 색을
>    물려받고 있었다. 색 별칭을 `--text-meta-color` 로 갈라 해소했다.
>    (`apps/admin` 이 "tokens.css 의 기존 버그"라고 적고 자기 쪽에서 우회하던 것이 이것이다.)
>
> ### `apps/admin` 은 색을 물려받지 않는다
>
> admin 은 자체 `--adm-*` 원시값으로 2층을 덮어쓰므로 팔레트 변경의 영향이 없다.
> 다만 **크기·모양 토큰은 물려받는다**(라운딩만 자체 값). tokens.css 에 2층 별칭을
> **새로 추가할 때는 admin 에도 대응 값을 넣어야 한다** — `--line-soft` 를 안 넣었더니
> 어두운 콘솔의 표 구분선이 거의 흰색이 될 뻔했다.

## 1. 토큰은 어디에 있는가

**단일 출처: `packages/ui/src/styles/tokens.css`.** 그 파일이 HEX 를 두는 유일한 자리다.

> ⚠️ 이 저장소는 **Tailwind v4** 라 설정이 CSS 안에 있다(`@theme`). 스펙 원문의
> `tailwind.config.ts` + `shared/config/theme/tokens.ts` 구조는 v3 전제라 여기엔 없다.
> TS 에 값을 복제하면 두 곳이 반드시 갈라지므로, 값이 필요한 코드는 `var(--color-*)` 를 읽는다.
>
> **예외 하나**: `<canvas>` 는 CSS 를 모른다. `shared/libs/theme/tokens.ts` 의 `canvasColor()`
> 가 `getComputedStyle` 로 같은 토큰을 읽어 넘긴다(폴백 HEX 포함). 스토리 카드 내보내기가
> 여기 해당한다.

### MUST NOT
- 컴포넌트 코드에 **HEX 리터럴**을 쓰지 않는다.
- Tailwind 기본 팔레트(`emerald-500`, `amber-300`, `slate-400` …)를 쓰지 않는다.
  테마를 따라오지 않을 뿐 아니라, **분류마다 색을 주는 습관의 입구**가 된다(§3).

### 색 선택 근거

- **Primary 를 딥 그린틸로 잡은 이유**: (a) 예방접종·건강 데이터를 다루므로 의료·안전
  신호로 읽히는 초록이 도메인에 부합, (b) 반려동물 업계의 '자연·산책·건강' 연상,
  (c) 채도를 낮춰 원색 특유의 유치함 없이 SaaS 톤 확보.
- **'따뜻함'은 Primary 가 아니라 Caution(애프리콧) + 웜 오프화이트 배경이 담당**한다.
  역할을 분리해야 "따뜻하지만 가볍지 않은" 인상이 나온다.
- **순백 배경을 쓰지 않는 이유**: 반사 휘도가 높아 장시간 사용 시 눈부심이 크다.
  카드만 순백으로 띄워 위계를 만든다.
- **순검정 텍스트를 쓰지 않는 이유**: 흰 배경 위 순검정은 할레이션(글자 번짐)을 유발한다.
  웜 다크로 배경과 색온도를 통일한다.

### ⚠️ 스펙과 이름이 다른 곳: `secondary` → `caution`

스펙 원문은 애프리콧을 `secondary` 라 부른다. 이 저장소에서 `--secondary` 는 이미 shadcn 의
**"차분한 중립 표면"** 을 가리키고(버튼 `variant='secondary'` 등 다수), 같은 이름을 애프리콧으로
돌리면 `bg-secondary text-secondary-foreground` 조합이 전부 2.54:1 이 되어 **스펙 자신의
MUST NOT 을 어긴다.** 그래서 역할 이름(`caution`)으로 분리했다 — §3 배지 레벨 이름과도 맞는다.

### MUST NOT
- `caution`, `warning-fill`, `border` 위에 흰색 텍스트를 올리지 않는다 (모두 3:1 미만).
- `caution` / `warning-fill` 을 **텍스트 색**으로 쓰지 않는다.
- 본문 텍스트에 대비 4.5:1 미만 조합을 쓰지 않는다.

## 3. 배지 색 규칙 (가장 중요)

**배지 색은 분류가 아니라 긴급도만 인코딩한다.** 견종별·성향별·상태별로 색을 다르게 주면
사용자는 색을 읽지 않고 글자만 읽게 되고, 그 순간 배지는 정보가 아니라 장식이 된다.

| 레벨 | 클래스 | 의미 | 예시 |
| --- | --- | --- | --- |
| `normal` | `<Badge variant='normal'>` | 확인 완료, 신경 쓸 필요 없음 | 접종 정상, 중성화 완료, 이용 중 |
| `caution` | `<Badge variant='caution'>` | 오늘 신경 써야 함 | 알러지, 마킹, 접종 D-9, 승인 대기, 작성 중 |
| `critical` | `<Badge variant='critical'>` | 지금 조치 필요 | 종합백신 만료, 공격 이력, 미도착, 결제실패 |

### MUST
- 상태 배지는 **이 3단계로만** 표현한다. **4번째 색을 추가하지 않는다.**
- 판정 규칙은 `packages/shared/src/pet-safety.ts` 한 곳에 둔다 — 화면과 서버가 각자
  구현하면 **칩에 "주의 5"라고 써 놓고 눌렀을 때 3마리만 나온다.**

> job-052 에서 실제로 고친 것: 출석 상태 6개에 색 6개(muted/blue/emerald/red/amber/muted),
> 구독 상태 4개에 색 4개, 리포트 상태 2개에 색 2개가 각각 다른 파일에서 따로 칠해져 있었다.
> 같은 "정상"이 화면마다 다른 초록이었다.

## 4. 타이포그래피

폰트: **Pretendard Variable** (dynamic-subset, 각 앱 `layout.tsx` 에서 로드).

| 토큰 | 클래스 | mobile | tablet+ | 굵기 | 용도 |
| --- | --- | --- | --- | --- | --- |
| `display` | `text-display` | 32px | 36px | 600 | 대시보드 핵심 수치 |
| `title` | `text-title` | 24px | 26px | 600 | 섹션 제목 (`SectionHeading`) |
| `name` | `text-name` | 21px | 22px | 600 | 반려견/직원 이름, 화면 제목 |
| `body` | `text-body` | 17px | 18px | 400 | 기본 본문 |
| `label` | `text-label` | 15px | 16px | 600 | 배지, 캡션 (**최소 크기**) |

- 숫자: 전역 `font-variant-numeric: tabular-nums` (`tokens.css` 의 `html`).
  픽업 시각·잔여 회차가 세로로 나열되므로 자릿수 정렬이 필수다.
- 한 줄 최대 길이: 한글 기준 40자 → `max-w-prose-ko`.
- 긴 한글 문장에는 `break-keep`.

### 기본 스케일을 5단계로 접었다

`text-xs`→15px, `text-sm`→15px, `text-base`→17px, `text-lg`/`text-xl`→21px,
`text-2xl`→24px, `text-3xl`→32px 로 **토큰 정의 자체를 바꿨다.**

> 이유: 화면 194곳이 이미 `text-xs`(12px)·`text-sm`(14px)을 쓰고 있었고 둘 다 15px 하한을
> 어겼다. 화면마다 클래스를 갈아끼우면 다시 갈라진다(job-050 에서 같은 실수를 했다).
> **정의를 고치면 손대지 않은 화면도 규격을 만족한다.**

### MUST NOT
- **15px 미만 폰트 금지.** `text-[10px]` 같은 임의 값도 금지.
- 굵기는 **400 / 600 두 단계만**. `--font-weight-*` 토큰이 `font-medium`·`font-bold`·
  `font-extrabold` 를 전부 600 으로, `font-light` 를 400 으로 접어 두었으므로
  기존 클래스를 그대로 써도 어긋나지 않는다.

| 카드 간격 | 12px | `gap-3` | |
| 리스트 행 높이 | 96px 이상 | `min-h-row` | 아바타 56px + 배지 2줄 |
| 섹션 간격 | 32px | `space-y-8` | 스크롤 시 청크 구분 |
| 화면 좌우 패딩 | 20px | `px-5` (PageShell 고정) | |

### 버튼 크기는 네 개뿐이다

| size | 높이 | 쓰는 곳 |
| --- | --- | --- |
| `xs` | 40px | `@pawlog/ui` **내부 조립용**(combobox clear 등). 화면 코드 금지 |
| `sm` | 48px | **데스크톱 관리 콘솔(`apps/admin`) 표 안 전용.** 마우스를 전제한다 |
| (미지정) | **64px** | **기본.** 손가락으로 누르는 모든 곳 |
| `lg` | 64px | 하단 고정 주 행동(CTA). 높이는 같고 패딩·글자가 크다 |

- ⚠️ **`apps/web` 화면 코드에서 `sm`/`xs` 를 쓰지 않는다.** 어기면 젖은 손 요구사항이
  조용히 깨진다 — 화면은 멀쩡해 보이고 현장에서만 틀린다.
- 버튼에 `h-*`/`px-*` 를 직접 붙이지 않는다. 필요하면 size 를 고른다.
- `w-full` 은 하단 고정 액션·폼 제출에만.

### 입력도 같은 눈금을 쓴다 (job-057)

`Input` · `Textarea` · `Select` · `NativeSelect` 의 높이는 **버튼과 같은 스케일**이다.

| size | 높이 | 쓰는 곳 |
| --- | --- | --- |
| `xs` | 40px | `@pawlog/ui` 내부 조립용. 화면 코드 금지 |
| `sm` | 48px | 데스크톱 콘솔(`apps/admin`) 표 헤더의 검색창 등 |
| (미지정) | **64px** | **기본.** 버튼 `default` 와 같은 `h-touch` 토큰을 참조한다 |

- ⚠️ **`size` 가 아니라 `inputSize` 다** (`<Input inputSize='sm'>`). 네이티브 `<input>` 에
  이미 `size`(표시 문자 수) 속성이 있어 이름이 겹치면 DOM 으로 새어 나간다.
- **왜 같은 눈금이어야 하나**: 검색창처럼 입력과 버튼을 나란히 두는 자리가 이 저장소에만
  18곳이다. 눈금이 갈리면 그 18곳이 전부 어긋나 보이고, 화면마다 `className='h-touch'` 로
  덧칠하기 시작하면 다시 제각각이 된다. job-052 가 버튼만 44→64px 로 올렸을 때 입력은
  shadcn 기본값 32px 에 남아 정확히 그 상태였다.
- **한 행 안에서는 입력·버튼·셀렉트의 size 를 반드시 맞춘다.** 관리 콘솔 표 헤더처럼
  `sm` 을 쓰는 자리는 그 행 전체를 `sm` 으로 통일한다(칩·검색·페이지네이션까지).

## 7. 인터랙션 규칙

| | 규칙 |
| --- | --- |
| MUST NOT | **스와이프 제스처로 주요 액션**(등원/하원, 삭제)을 트리거하지 않는다. 젖은 손가락은 드래그 궤적이 튀어 인식률이 낮고, 실패해도 사용자는 뭘 잘못했는지 모른다 |
| MUST NOT | 롱프레스를 **유일한** 진입 경로로 쓰지 않는다 |
| MAY | **조회**만 하는 스와이프는 쓴다 — 사진 캐러셀(`PhotoCarousel`)처럼 빗나가도 되돌릴 것이 생기지 않는 경우. 대신 데스크톱용 화살표 같은 두 번째 경로를 함께 둔다 |
| MUST | 등원/하원은 **카드 우측 64×64 버튼**으로 처리한다 (`<DogCard.Root action={…}>`). 카드 높이를 채우는 색 띠로 만들지 않는다 — 그 크기의 면은 버튼이 아니라 카드의 일부로 읽힌다 |
| MUST | 상태 변경 액션은 실행 후 **8초 되돌리기**(`useUndoToast`)를 제공한다 |
| MUST | 상세 조회는 페이지 이동이 아니라 **`BottomSheet`** 로 띄워 목록 스크롤 위치를 보존한다 |
| MUST | `BottomSheet` 최상단에 **보호자 전화 걸기** 버튼 (`guardianPhone` prop) |
| MUST | 스크롤 영역에는 `overflow-y-auto` 와 **`overflow-x-hidden` 을 같이** 준다. CSS 규칙상 한 축만 지정하면 나머지 축의 `visible` 이 `auto` 로 승격돼, 조금만 넓은 자식이 있어도 가로 스크롤바가 생긴다 |
| MUST | 모달 폭은 `sm:max-w-*` 로 지정한다. `max-w-md` 처럼 브레이크포인트 없이 주면 `DialogContent` 기본값의 `sm:max-w-sm`(384px)이 **데스크톱에서 이긴다** — 넓히려던 모달이 오히려 좁아진다 |

### 되돌리기는 화면만 되돌리는 게 아니다

등원 체크는 ① 회수권을 1회 깎고 ② 보호자에게 알림톡을 보낸다. 프런트에서 상태만 되돌리면
**오터치 한 번에 보호자가 조용히 1회를 잃는다.** 그래서 `POST v1/attendances/:id/undo-check-in`
이 상태와 차감을 함께 되돌리고, 원장(ledger)은 append-only 이므로 **역분개 행을 쌓는다**
(원본 행의 `attendanceId` 를 떼어 재체크 시 차감이 건너뛰어지지 않게 한다).

이미 나간 알림톡은 회수할 수 없다 → 토스트가 "보호자에게 알림이 나갔습니다"를 밝힌다.
**되돌릴 수 없는 것을 되돌릴 수 있는 척하지 않는다.**

### 되돌리기를 붙일 수 없는 동작

외부로 이미 나간 발행처럼 정말 못 되돌리는 것은 `useUndoToast` 를 쓰지 말고
**하단 시트로 미리** 확인받는다.

## 10. 정보 위계 — 홈은 메뉴가 아니라 오늘이다

### 매장 홈 `/tenant/[tenant]` (§6.2)

우선순위 기준은 '중요도'가 아니라 **"지금 안 보면 되돌릴 수 없는 정도 × 오전에만 대응
가능한 정도"** 다. `widgets/today-board` 가 이 순서를 고정한다.

| 순위 | 블록 | 근거 |
| --- | --- | --- |
| 0 | 오늘 사진 0장 (`PhotoGapAlert`) | 시간이 지나면 되돌릴 수 없는 유일한 항목 |
| 1 | **오늘 등원 현황** `14 / 18마리` + 미도착 이름 + 아직 안 온 아이 | 미도착은 즉시 보호자 확인 전화로 이어져야 한다. "몇 마리 왔나"보다 **"지금 누가 올 차례인가"** 가 실무 정보 |
| 2 | **오늘 주의할 아이** | 사고 예방 정보라 사후 확인이 무의미. 1위에서 등원 여부를 확인한 직후에 봐야 조회 맥락이 이어진다 |
| 3 | **훈련사 배치 비율** `1 : 6` | 안전 직결. 결원 시 **오전에만** 대체 인력 확보 가능. 단순 출근 인원이 아니라 **비율**이어야 판단 기준이 된다 |
| 4 | **하원·픽업 타임라인** | 오후 혼잡 구간을 오전에 미리 인지시켜 배치를 조정하게 한다 |
| 5 | **정기권 잔여** | 하원 시 보호자를 만나는 타이밍에 재결제 대화를 걸 수 있다. 시간 민감도 최저 |

하단 고정 퀵액션 3개: `등원 처리` (primary) / `알림장` / `사진`.
그 아래에 관리 메뉴 격자.

**예방접종 만료를 별도 카드로 만들지 않는 이유**: "접종 만료 2건"을 보면 결국 그 아이가
오늘 오는지 확인하러 등원 목록으로 다시 들어가야 한다. 접종 상태는 **1순위 등원 목록 안에서**
`critical` 로 잡는 것이 동선이 짧다. 정보를 카드 개수로 나열하는 것보다 실제 동선 위에
얹는 편이 인지 부하를 더 줄인다.

**한 응답으로 받는다** (`GET v1/admin/dashboard`) — 블록마다 따로 부르면 우선순위가
**로딩 순서**로 바뀐다(늦게 온 것이 늦게 뜬다).

### 보호자 홈 `/app`

오늘 우리 아이 사진/알림장이 **바로** 보인다. 없으면 "아직 오늘 소식이 없어요"와 지난 기록.
바로가기는 그 아래, **최대 4개**.

### 하단 탭

최대 5개(엄지 도달 범위). 라벨은 2~3글자 명사. 매장 영역과 개인 영역의 탭은 섞지 않는다.

## 11. 원생 목록 `/tenant/[tenant]/pets` (§6.1)

**카드에 담을 정보를 '조회용'과 '사고 예방용'으로 나누고, 사고 예방용만 표면에 올린다.**
체중·생일·보호자 주소는 상세 시트로 내려도 되지만, 알러지·공격성·접종 만료는 한 뎁스만
숨겨도 급할 때 놓친다.

- **표가 아니라 카드**다. 8열 표는 모바일에서 가로 스크롤이 생겨, 한 아이를 보려면 좌우로
  밀어야 했고 그 상태로는 알러지도 접종 만료도 화면 밖에 있었다. 이 화면은 사무실 책상이
  아니라 **현관**에서 쓰인다.
- **기본 정렬은 픽업 시각 오름차순** (이름순 아님). 서버가 정한다
  (`AdminService.PET_DEFAULT_SORT`). 등하원 시각이 제각각이고 15~18시가 가장 혼잡해서,
  픽업 시각 순 목록이 그대로 **오후 작업 순서표**가 된다. 이름 검색은 검색창이 대체한다.
- 필터 칩: `전체 / 등원 중 / 등원 예정 / 하원 완료 / 주의`. 개수는 **매장 전체 기준**
  (`GET v1/admin/pets/summary`) — 페이지 기준이면 "주의 0"인데 다음 페이지에 주의 아이가 있다.
- **카드 테두리 승격**: 접종 만료 **또는** 공격 이력이면 `border-2 border-danger`.
  배지 하나로는 스크롤 중에 놓친다 — 배지는 멈춰서 봐야 읽히고, 테두리는 지나가면서도 보인다.

### 접종 만료 견의 등원 처리 (MUST)

if (expiredVaccinationTypes.length > 0) {

원장이 사정을 알고 받는 경우가 실제로 존재하며(오늘 접종하러 가는 길에 맡기는 등),
아예 막으면 **앱 밖에서 처리해버려 기록이 사라진다.**

## 12. 도메인 규칙 — 안전 정보는 구조를 갖는다

알러지·성향·마킹·접종은 예전에 `Pet.careNote` 자유 텍스트 한 칸에 문장으로 들어갔다.
그러면 **카드 표면에 올릴 수도, 필터를 걸 수도 없다.** job-052 에서 컬럼으로 분리했다.

### MUST
- `temperaments` 는 **형용사가 아니라 상황 서술**로 저장한다.
  `'소심함'` ✗ / `'대형견 무서워함'` ○ — 훈련사가 합사 그룹을 나눌 때 바로 쓸 수 있어야 한다.
- `marksIndoors`·`mountingBehavior`·`hasBiteHistory` 처럼 **시설 운영에 직접 영향을 주는
  항목**은 자유 텍스트 메모와 분리된 별도 필드로 둔다. 이후 "마킹 잦은 아이만" 필터가 필요해진다.
- 접종 **상태(valid/expiring_soon/expired)를 저장하지 않는다.** 저장하면 날짜가 지나도
  갱신되지 않아 "만료됐는데 정상으로 표시되는" 최악의 실패가 난다. 조회 시점에 계산한다
  (`resolveVaccination`).
- 접종 **기록이 아예 없으면 `caution`** 이다. `normal` 로 두면 "확인했고 문제없다"와
  "아무도 확인한 적이 없다"가 화면에서 같아 보인다.

기존 `careNote` 문장을 **자동 파싱해 옮기지 않았다** — 잘못 파싱한 알러지는 없는 것보다
위험하다. 원장이 아이를 열어 확인하며 채우는 것이 맞고, 그때까지 빈 값이 정직한 상태다.
입력 자리는 `features/pet/edit-pet` 의 **맨 위** 섹션이다.

## 13. 구현 체크리스트

새 화면/컴포넌트를 올리기 전에 훑는다. 괄호는 검증 명령.

- [ ] 인터랙티브 요소가 64px 터치 타겟인가 (`grep "size='sm'" apps/web/src` → 0건)
- [ ] 입력과 옆 버튼의 높이가 같은가 — 한 flex 행 안의 `Input`/`Select`/`Button` size 가
      전부 같은지 본다. 화면에서 `className='h-…'` 로 맞추고 있으면 그건 정의를 고칠 신호다
      (`grep -E "<(Input|Textarea|SelectTrigger)[^>]*h-" apps/web/src apps/admin/src` → 0건)
- [ ] 본문 대비 4.5:1 이상인가
- [ ] `caution`·`warning-fill`·`border` 위에 텍스트가 없는가 (`grep "bg-caution\b"` → 채움 전용만)
- [ ] 15px 미만 폰트가 없는가 (`grep "text-\[[0-9]" apps/web/src` → 0건)
- [ ] 굵기가 400/600 만인가 (`--font-weight-*` 토큰이 강제)
- [ ] 숫자에 `tabular-nums` 가 적용됐는가 (`tokens.css` 의 `html` 이 전역 적용)
- [ ] 배지 레벨이 3단계를 벗어나지 않는가 (`grep -E "(bg|text|border)-(emerald|amber|slate|...)-[0-9]"` → 0건)
- [ ] 상태 변경마다 8초 Undo 가 있는가 (`useUndoToast`)
- [ ] 주요 액션이 스와이프·롱프레스에만 의존하지 않는가
- [ ] 상세가 `BottomSheet` 로 열려 목록 스크롤이 보존되는가
- [ ] 접종 만료 견의 등원 버튼이 disable 되어 있지 않은가
- [ ] `entities` 가 `features`/`widgets` 를 import 하지 않는가 (`grep 'from "@/features/' apps/web/src/entities` → 0건)
- [ ] 컴포넌트 코드에 HEX 리터럴이 없는가 (`canvasColor` 브리지 제외)

## 14. 검증이 필요한 가정

이 스펙은 다음 가정 위에 세워져 있으며, **원장 인터뷰로 검증해야 한다.**

1. **대시보드 3순위(훈련사 배치 비율)** 는 일정 규모 이상 업장 기준이다. 1~2인 사업장에서는
   무의미할 수 있다.
2. **픽업 시각 기본 정렬**이 실제 업무 순서와 일치하는지 확인이 필요하다.
3. **성향 정보의 입력 주체**(원장 vs 훈련사)에 따라 입력 UI 위치가 달라진다.
   지금은 원장용 `EditPetDialog` 안에 있다.

> 권장 검증 질문: **"아침에 출근해서 제일 먼저 확인하시는 게 뭐예요?"** — 열린 질문으로
> 던지면 대시보드 우선순위가 바로 검증된다. 대시보드 순서는 코드 몇 줄이지만, 잘못 잡으면
> **매일 반복해서 틀리는 종류의 실수**다.
