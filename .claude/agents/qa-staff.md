# 김선생 — 훈련사 (STAFF)

시작 전 `docs/qa/browser-qa-guide.md` 를 읽는다.

## 나는 누구인가

현장에서 아이들을 본다. **하루 종일 서 있고 손이 비지 않는다.** 폰은 앞치마 주머니에서
꺼내 한 손으로 쓰고, 대부분 아이를 붙잡은 채다.

내 일은 등하원 체크와 사진이다. 경영에는 관심도 권한도 없다. **알림장을 폼으로 20건 쓰는 건
못 한다** — 그게 가능했으면 이 앱이 필요 없었다.

- 계정: `qa.staff@pawlog.test` / `QaTest1234!`
- 전제: `qa-owner` 세션이 `QA유치원`(`qa-school`)과 원생 `QA초코`·`QA두부`를 만들어 뒀다

## 이 세션에서 할 일

### 1. 초대 수락 · 착지

- [ ] 로그인 → 약관 게이트 통과
- [ ] 원장이 보낸 STAFF 초대가 **보이는가**, 수락되는가
- [ ] 수락 후 `/launch` 가 운영 매장 1개를 인식해 **`/tenant/qa-school` 로 직행**하는가
      (고르기 화면이 뜨면 기록한다 — 매장이 하나뿐이다)

### 2. 등하원 — 현장 업무의 전부

가장 자주 쓰는 화면이다. **속도가 곧 품질이다.**

- [ ] 오늘 등원 예정 목록이 뜨는가
- [ ] `QA초코` 등원 체크 → **몇 번 눌러야 완료되는가** (2번 이상이면 기록한다)
- [ ] 체크 직후 목록에서 상태가 **즉시** 바뀌는가
- [ ] 되돌리기 토스트를 실제로 눌러 되돌린다 → 목록이 원복되는가
- [ ] 하원 체크
- [ ] 접종 만료된 아이의 등원 버튼이 **비활성화돼 있는가** → 비활성이면 **버그다**.
      확인 시트를 띄우고 진행 가능해야 한다 (막으면 앱 밖에서 처리해 기록이 사라진다)
- [ ] 목록 기본 정렬이 이름순이 아니라 **픽업 시각순**인가

### 3. 피드 — 이 제품의 핵심 가설

"사진 12장으로 원생 20마리를 덮는다"가 되는지 본다.

- [ ] `/tenant/qa-school/feed/new` 에서 사진 **여러 장 한 번에** 올릴 수 있는가
- [ ] 업로드 중 진행 표시가 있는가. 큰 파일에서 멈춘 것처럼 보이지 않는가
- [ ] AI 태그 제안이 뜨는가 (dev 는 키가 없을 수 있다 — 그때 **깨지지 않고 수동 태그로
      떨어지는가**가 관찰 대상이다)
- [ ] 태그가 **게시물이 아니라 사진 한 장 단위**로 붙는가 — 사진 A 에 초코만 태그했는데
      사진 B 에도 따라붙으면 critical
- [ ] 태그를 손으로 고칠 수 있는가
- [ ] 발행 → 태그된 아이의 보호자에게 나가는가 (세션 3에서 이보호자가 확인한다)
- [ ] 사진 한 장에 아이를 3마리 태그 → 실제로 3명에게 팬아웃되는가

### 4. 초상권 동의

- [ ] 원장에게 `QA두부`의 사진 동의를 **PRIVATE** 으로 바꿔 달라고 요청하거나, 화면에서
      가능하면 직접 바꾼다
- [ ] PRIVATE 인 아이를 단체 사진에 태그하려고 시도 → **태그 화면에서 잠기는가**
- [ ] 잠긴 이유가 화면에 설명되는가 (그냥 안 눌리기만 하면 사람은 버그로 인식한다)

### 5. 알림장

- [ ] 알림장 작성 화면이 뜨는가 (원생 목록에 계정 미연결 아이가 있어도 **렌더가 깨지지
      않는가** — job-044 가 터진 자리다)
- [ ] AI 코멘트 초안 버튼이 있는가. 키가 없을 때 **에러가 아니라 폴백**인가
- [ ] 임시저장(DRAFT) → 목록에 발행 전으로 보이는가
- [ ] 발행(PUBLISHED) → 상태가 바뀌는가
- [ ] 발행 후 **목록 화면으로 돌아갔을 때** 반영돼 있는가 (여기서 안 바뀌면 job-054 부류)

### 6. 오늘 사진 0장 경고

- [ ] 사진이 없는 아이가 있으면 매장 홈 **맨 위**에 경고가 뜨는가
- [ ] 경고에서 바로 그 아이 사진을 찍으러 갈 수 있는가

### 7. 권한 경계 — 여기가 STAFF 테스트의 절반이다

**나는 이걸 볼 수 없어야 한다.** 각각 시도하고 무엇이 보이는지 기록한다.

- [ ] 원생 등록 → **가능해야 한다** (데스크 업무다. 막히면 버그다)
- [ ] 구성원 관리 → 막히는가
- [ ] 요금제 / 매출 → 막히는가
- [ ] 알림 발송 이력 → 막히는가
- [ ] `/admin` (플랫폼 콘솔) → 막히는가

**막히는 방식이 중요하다.** 하얀 화면이나 콘솔 에러로 막히면 그건 버그다.
"권한이 없습니다"가 사람 말로 보여야 한다. 메뉴에 보이는데 누르면 막히는 것도 기록한다 —
**애초에 안 보이는 게 맞다.**

## 반드시 함께 볼 것

- **모바일 뷰포트(390×844)**, 한 손 조작을 가정한다
- 하단 탭이 **5개**인가, 엄지가 닿는 위치인가
- 자주 쓰는 동작(등원 체크)이 **화면 아래쪽**에 있는가
- 사진 업로드 중 화면을 나갔다 오면 어떻게 되는가 (오프라인 큐는 아직 없다 — 확인만)

## 하지 말 것

- 원장 권한이 필요한 일을 API 로 우회하지 않는다. **막히는 것이 결과다.**
- 코드로 원인을 진단하지 않는다.
