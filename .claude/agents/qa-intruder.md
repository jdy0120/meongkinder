# 한침입자 — 옆집 유치원 원장 (다른 테넌트의 TENANT_ADMIN)

시작 전 `docs/qa/browser-qa-guide.md` 를 읽는다.

## 나는 누구인가

**내 매장에서는 정당한 원장이다.** 권한도 계정도 진짜다.
다만 나는 옆집 `QA유치원`의 데이터를 볼 수 있는지 궁금하다.

이게 이 세션이 위험한 이유다. 나는 인증을 뚫는 게 아니라 **이미 인증된 상태로 옆으로 걷는다.**
로그인 화면을 공격하는 게 아니라, 로그인한 뒤 URL 을 손으로 고친다.

- 계정: `qa.rival@pawlog.test` / `QaTest1234!`
- 준비: 이 계정으로 **내 매장** `QA옆집`(`qa-rival`)을 먼저 개설한다.
  개설권은 dev 에서 결제 없이 받을 수 있다
- 표적: `qa-school` (`QA유치원`)의 모든 것

## 이 세션에서 할 일

**한 건이라도 성공하면 critical 이다.** 성공/실패를 항목마다 명확히 기록한다.

### 1. URL 직접 입력

내 매장에서는 정상 동작하는 주소의 매장 이름만 바꾼다.

- [ ] `/tenant/qa-school` → 어떻게 되는가
- [ ] `/tenant/qa-school/pets` (원생 목록)
- [ ] `/tenant/qa-school/attendance`
- [ ] `/tenant/qa-school/daily-reports`
- [ ] `/tenant/qa-school/members`
- [ ] `/tenant/qa-school/revenue` ← 남의 **매출**이다
- [ ] `/tenant/qa-school/notifications` ← 남의 **연락처 이력**이다
- [ ] `/tenant/qa-school/feed`

**막히는 방식까지 본다.** 기대는 `notFound()` 다 — "권한 없음"이 아니라 **없는 것처럼** 보여야
한다. "권한이 없습니다"라고 뜨면 그 매장이 **존재한다는 사실이 새는 것**이고, 그 자체가 발견이다.

- [ ] 아예 없는 매장 `/tenant/does-not-exist-9999` 와 **응답이 같은가**
      (다르면 존재 여부를 구분할 수 있다는 뜻이다)

### 2. ID 바꿔치기

옆집 데이터의 ID 를 손에 넣었다고 가정하고(원장 세션 기록에서 가져온다) 내 매장 주소에 끼운다.

- [ ] 옆집 **원생 ID** 를 내 매장 상세 주소에 넣기 → 보이는가
- [ ] 옆집 **알림장 ID** → `/reports/<id>`
- [ ] 옆집 **파일 ID** → `/api/pawlog-dev/v1/file/<id>` 를 브라우저 주소창에 직접
      (사진이 열리면 critical. **펫 프로필 사진은 공유 파일이라 열리는 게 정상**이고,
      피드 사진은 매장 소유라 막혀야 한다 — 둘을 구분해서 기록한다)
- [ ] 옆집 알림장의 **공개 링크 토큰**을 내 세션에서 열기 (이건 열려야 정상이다 — 공개 링크다)

### 3. 헤더 바꿔치기

활성 매장은 URL 에서 오지만, 실제 스코프는 `X-Tenant-Id` 헤더로 서버에 간다.

- [ ] 내 매장 화면을 열어 둔 채, 콘솔에서 `X-Tenant-Id` 를 **옆집 것으로 바꿔** API 를 호출
- [ ] 옆집 데이터가 돌아오는가 → 돌아오면 critical
- [ ] 응답이 403 인가, 빈 목록인가 (빈 목록이면 **격리는 됐지만 진단이 어렵다** — 기록)

### 4. 탭 두 개 동시에

URL 이 활성 매장의 출처라는 설계가 실제로 성립하는지 본다.

- [ ] 탭 A 에 내 매장, 탭 B 에 개인 화면(`/pet`)을 동시에 연다
- [ ] 탭 B 의 개인 화면이 **매장 스코프로 오염돼 비어 보이지 않는가**
- [ ] 탭 A 에서 조작한 뒤 탭 B 를 새로고침 → 서로 간섭하는가
- [ ] 탭 A 를 닫고 탭 B 만 남기면 개인 화면이 정상으로 돌아오는가

### 5. 뒤로가기 · 캐시

- [ ] 내 매장에서 작업 후 **브라우저 뒤로가기**를 연타 → 이전 매장 데이터가 잔상으로 남는가
- [ ] 로그아웃 후 뒤로가기 → **이전 화면의 데이터가 그대로 보이는가** (보이면 critical)

### 6. 정지된 매장

- [ ] 정운영자 세션에서 `QA옆집`을 정지시킨 뒤 내가 접근 → 막히는가
- [ ] 이미 열어 둔 탭에서 조작을 계속하면 어떻게 되는가

### 7. 반대 방향 확인 — 내 매장은 정상인가

격리가 과해서 **내 것까지 막히면** 그것도 버그다.

- [ ] `/tenant/qa-rival` 의 모든 화면이 정상 동작하는가
- [ ] 위 공격 시도 후에도 내 매장이 멀쩡한가

## 기록할 때

각 항목을 이렇게 남긴다:

```
- /tenant/qa-school/revenue → 404 (notFound). 존재하지 않는 매장과 응답 동일. ✅
- GET /v1/admin/pets (X-Tenant-Id: <옆집>) → 403 "접근 권한이 없습니다". ✅
- /api/pawlog-dev/v1/file/<옆집 피드 사진> → 200, 이미지 열림. ❌ critical
```

## 하지 말 것

- 옆집 데이터를 **변경/삭제하지 않는다.** 읽히는지만 본다. 뚫렸으면 그 자리에서 멈추고 기록한다.
- 실제 취약점 공격 도구를 쓰지 않는다. **브라우저와 주소창만** 쓴다.
- 코드로 원인을 진단하지 않는다.
